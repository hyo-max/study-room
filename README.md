# 자습실 · Study Room

> 집중할 수 있는 환경을 함께 만듭니다.

**지정 주제 1 — Vue 3 + NestJS 자습실 예약 관리 MVP**

강사는 자습실과 학생을 관리하고, 학생은 방문을 신청·변경·취소합니다. 현재 신청 상태와 모든 변경 이력을 분리해 저장합니다. 별도 DB, 클라우드 계정, API 키가 필요하지 않습니다.

## 빠른 시작

- Node.js **22 이상**, npm 10 이상
- 처음 실행할 때만 npm 패키지 다운로드를 위한 인터넷 연결 필요

```bash
npm ci
npm run dev
```

- 브라우저: **http://127.0.0.1:5173**
- API: http://127.0.0.1:3000/api
- 첫 진입 화면에서 **강사 / 학생**을 선택합니다. 학생은 이름을 선택한 뒤 입장합니다.
- 서비스 내부에는 역할 전환 버튼이 없습니다. 다른 역할로 이용하려면 **나가기**로 진입 화면에 돌아갑니다. 새로고침 시에도 다시 선택합니다.
- 이는 과제용 진입 동선이며 실제 로그인/계정 인증은 아닙니다.
- 최초 실행 시 가상의 학생 6명과 실행일 다음날부터 시작하는 자습실 3개가 생성됩니다. 연락처는 데모 값입니다.
- 다른 로컬 서비스가 3000 또는 5173 포트를 사용하면 해당 서비스를 종료한 후 실행하세요.

### 빌드된 앱 실행

```bash
npm run build
npm start
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)에서 빌드된 Vue 앱과 API를 같은 서버로 제공합니다. 개발 모드와 프로덕션 실행을 동시에 사용하지 마세요. 서버는 로컬 루프백에 바인딩합니다.

### 테스트

```bash
npm test       # 도메인·HTTP·프론트 상태·시간 입력 회귀 테스트
npm run build # API TypeScript, Vue 타입 검사, Vite 빌드
npm run check # 위 검증 일괄 수행
```

테스트는 운영 데이터 대신 OS 임시 디렉터리를 사용하고 실행 후 제거합니다. HTTP 통합 테스트는 임시 포트에 서버를 띄워 실제 요청을 보냅니다.

### 데이터 보관 / 초기화

- 기본 데이터 파일: `apps/api/data/store.json` (Git 제외)
- 서버를 종료하고 이 파일을 삭제하면 다음 실행 시 초기 샘플 데이터를 생성합니다.
- `DATA_FILE=/절대/경로/store.json npm start`로 경로를 변경할 수 있습니다.
- 실행 명령은 프로젝트 루트에서 실행하세요. npm workspace 스크립트가 API 디렉터리 기준으로 데이터를 저장합니다.
- `.env`를 자동 로드하지 않습니다. 설정이 필요하면 셸 환경 변수를 사용하세요.

## 주요 정책

1. 정원은 **자습실 전체의 활성 신청 수**입니다. 시간대별 좌석/입퇴실 관리가 아닙니다.
2. 방문 시간은 운영 시작과 종료 시각을 **모두 포함**합니다. 운영 시작은 종료보다 빨라야 합니다.
3. `(roomId, studentId)`당 신청 객체는 한 건입니다. 취소 후 재신청 시 동일 ID를 활성화하고 `REAPPLIED` 이력을 남깁니다.
4. 현재 활성 신청 인원보다 정원을 줄이거나, 기존 신청 시간을 벗어나도록 기간을 수정하면 **409 오류**로 거절합니다. 자동으로 학생의 계획을 변경하지 않습니다.
5. 자습실 삭제 시 `deletedAt`을 기록하고 활성 신청을 모두 취소하며 사유를 이력에 남깁니다. 목록·상세·신청 대상에서 제외하지만 학생의 내역에는 삭제 여부가 표시됩니다.
6. 학생은 본인 신청만 변경할 수 있습니다. 취소된 신청은 수정·중복 취소할 수 없습니다. 같은 시간으로 수정하면 불필요한 이력을 만들지 않습니다.
7. 활성 신청이 있는 학생의 삭제는 거절합니다. 이력 보존을 위해 학생도 Soft Delete합니다.
8. 서버 저장은 UTC ISO 8601, 입력·출력 화면은 **Asia/Seoul(KST)**입니다. 브라우저 OS 시간대와 무관하게 KST로 처리합니다.
9. 과제에 과거 신청 금지 규칙이 없어 과거 운영 기간과 방문 시각도 허용합니다. 신청 가능 여부는 삭제·정원 기준입니다. 실제 운영 시 서버 시각 기반 마감 정책을 추가할 수 있습니다.
10. 강사는 1개의 공용 워크스페이스입니다. 실제 강사별 소유권과 인증은 이 과제에서 생략했습니다.

## 기술 스택과 선택 이유

| 기술                                 | 선택 이유                                                       |
| ------------------------------------ | --------------------------------------------------------------- |
| Vue 3 / Composition API / TypeScript | 역할·목록·모달 상태를 명시적으로 관리하고 입력/화면 타입을 검사 |
| Vite                                 | 작은 MVP에 적합한 빠른 개발 서버와 정적 번들                    |
| NestJS / Express                     | HTTP 라우팅과 DI를 제공하고 서비스/저장소 확장이 쉬움           |
| JSON 파일                            | 과제에서 허용한 저장 방식. DB 설치 없이 즉시 실행 가능          |
| Node test runner / tsx               | 별도 테스트 프레임워크 없이 도메인·실제 HTTP 회귀 검증          |
| npm workspaces                       | 프론트·백엔드 의존성과 실행 명령을 저장소 하나로 관리           |

이 프로젝트의 데이터 규모와 단일 프로세스 전제에 맞춰 JSON 파일 저장을 택했습니다. **다중 서버·대용량 운영용 DB를 대체하는 설계는 아닙니다.**

## 아키텍처와 동시성

```mermaid
flowchart LR
  User[강사 / 학생] --> Vue[Vue 3 화면]
  Vue -->|JSON HTTP + 역할 헤더| Controller[NestJS Controller]
  Controller --> Service[Service: 규칙 / 소유권 검증]
  Service --> Store[Store: 동기 트랜잭션]
  Store --> JSON[(JSON 파일)]
```

- Controller: HTTP 요청을 도메인 서비스에 전달, 역할/ID 해석.
- Service: 입력 검증, 정원·중복·소유권 검사, 상태 전이와 이력 생성.
- Store: 복제된 상태를 변경하고 임시 파일에 쓴 후 rename. 쓰기가 성공한 후에만 메모리 상태를 교체.
- 트랜잭션에는 `await`가 없습니다. **단일 Node 프로세스**의 이벤트 루프에서 검사→변경→파일 쓰기 전체를 동기 처리해 동일 프로세스의 동시 요청 사이에 정원 경쟁이 발생하지 않도록 합니다.
- 상태와 이력은 한 번의 저장으로 반영됩니다. 검증 실패 시 둘 다 유지됩니다.
- 파일은 원자적 교체를 사용하지만 fsync 기반 전원 장애 내구성은 보장하지 않습니다. JSON 구문이 깨진 기존 파일은 덮어쓰지 않고 시작에 실패합니다.
- 확장 시 Postgres 트랜잭션 + 자습실 행 잠금 + `(room_id, student_id)` 유니크 제약으로 교체합니다. 프로세스를 여러 개 띄워 같은 JSON 파일을 공유하면 안 됩니다.

자세한 내용: [아키텍처·컨벤션](docs/architecture.md), [데이터 모델](docs/schema.md), [API](docs/api.md).

## 고민과 한계

- **현재 상태 vs 이력**: 목록 조회를 단순하게 유지하면서 변경 전후의 시각과 취소 사유를 모두 남기기 위해 별도 컬렉션을 선택했습니다. 이벤트 소싱까지 도입하지 않았습니다.
- **변경 정책**: 기간 변경으로 학생 일정을 자동으로 이동시키기보다 충돌을 명확히 알리도록 했습니다. 삭제는 명시적 확인을 받은 후 일괄 취소합니다.
- **인증 생략**: `x-role`, `x-student-id`는 역할 선택 데모용입니다. 헤더를 바꾸면 다른 역할을 사용할 수 있으므로 실제 인증·인가가 아닙니다. 실서비스에서는 서버 세션/JWT에서 사용자 신원을 받아야 합니다. 학생 선택용 목록 역시 인증 없이 제공되는 데모 데이터입니다.
- **범위 제어**: 좌석 배치, 대기 신청, 알림, 페이징, 수정 충돌 버전 관리, 로그인, 배포는 포함하지 않았습니다.
- **화면 구조**: App.vue는 화면 조합과 메뉴 이동을 담당합니다. 6개 컴포넌트가 진입·자습실 목록·상세·학생 목록·내 신청·입력 모달을 나누어 맡습니다. 목록 컴포넌트는 타입이 지정된 이벤트로 작업을 요청하고, 폼과 저장은 WorkspaceDialog.vue가 담당합니다. API·상태 관리는 workspace.ts, 시간 변환은 date-time.ts로 분리했습니다.
- **동기 I/O**: 소규모에서 규칙의 원자성을 이해하기 쉽지만 파일이 커지면 요청을 막습니다. 대규모에서는 DB 기반 저장소가 필요합니다.
- 폰트는 Google Fonts를 선택적으로 사용하며 네트워크가 없어도 시스템 글꼴로 작동합니다. 앱의 핵심 기능은 외부 API에 의존하지 않습니다.
- AI 도구를 사용해 구현·테스트·문서화를 보조했습니다. 면접 전 [코드 설명 가이드](docs/review-guide.md)의 질문과 코드를 직접 확인하는 것을 권합니다.
