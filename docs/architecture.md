# 아키텍처와 컨벤션

## 책임 분리

HTTP 계층은 입력된 ID/역할을 변환하고 Service를 호출합니다. 업무 규칙은 Service에 모았습니다. Store는 JSON 저장 방식만 담당하며 NestJS를 참조하지 않습니다. Nest 모듈은 팩토리 provider를 이용해 Store → Service → Controller를 주입합니다. 별도의 글로벌 서비스 싱글턴 생성은 하지 않습니다.

도메인 서비스가 Nest의 HTTP 예외를 사용하는 것은 소규모 MVP의 실용적 선택입니다. 다른 전송 계층이 필요해지면 도메인 오류를 별도로 정의하고 HTTP filter에서 매핑할 수 있습니다.

## 요청 처리

1. 프론트에서 선택한 역할 헤더를 전달합니다.
2. Controller가 역할 문자열과 정수 ID를 검사합니다.
3. Service가 강사 권한 또는 학생 신청 소유권을 확인합니다.
4. Store가 현재 상태를 복제합니다.
5. Service가 복제본에서 정원·중복·운영 기간을 검사하고 상태와 이력을 함께 변경합니다.
6. Store가 임시 파일을 저장하고 기존 파일을 교체합니다.
7. 저장 성공 시 메모리 상태를 교체하고 복제된 결과를 반환합니다.

쓰기 실패·검증 실패 시 메모리 상태를 변경하지 않습니다. 임시 파일은 다음 쓰기에 덮어씁니다. 단일 프로세스 전제이며 여러 프로세스 간 잠금은 제공하지 않습니다.

## 프론트

- 별도 역할 선택 진입 화면, 상단 주 메뉴, 목록/상세/내 신청, 모달 기반 폼으로 구성합니다. 학생은 진입 화면에서 이름을 선택합니다. 내부 화면에서는 현재 사용자와 나가기만 표시합니다.
- 서버를 단일 진실 공급원으로 사용합니다. 저장 성공 후 목록과 상세를 다시 읽습니다.
- 서버의 오류 메시지를 폼 내부에 표시하고 입력값을 유지합니다.
- workspace.ts가 요청 버전과 역할·학생 신원을 함께 비교해 이전 목록/상세 응답을 무시합니다. 화면 이동 후 도착한 상세 응답도 무시합니다. 삭제된 선택 학생은 첫 유효 학생으로 바꾸고, 학생이 없으면 내 신청 요청을 생략합니다.
- 저장 중 버튼 중복 클릭 방지, 삭제 확인, 모달 포커스 가두기/Escape/포커스 복원과 배경 inert를 적용합니다.
- 방문 이력은 학생에게 반환하지 않습니다. 강사는 시간순(오래된 것부터)으로 봅니다.
- 개발: Vite `/api` 프록시. 빌드 실행: Nest/Express가 정적 Vue 번들을 제공합니다. URL 기반 라우터가 없어 별도의 SPA fallback이 필요하지 않습니다.

## 입력과 오류

DTO 라이브러리 대신 inputs.ts의 필드별 명시 검증을 사용했습니다. HTTP body는 unknown으로 받고 객체 여부와 필드를 검증한 뒤 RoomInput, StudentInput, VisitInput으로 정규화합니다. 역할은 teacher/student 판별 유니온이며 student에는 studentId가 필수입니다. 알려진 필드만 읽으며 ID·정원은 양의 안전 정수, 이름은 길이 제한, 전화번호는 휴대전화 형식, 일시는 시간대가 명시된 ISO 형식으로 받습니다. 32KB JSON body 제한이 있습니다.

| HTTP | 의미                        |
| ---- | --------------------------- |
| 400  | 잘못된 입력, 운영 기간 위반 |
| 401  | 역할 헤더 없음/잘못된 역할  |
| 403  | 역할 제한 또는 타인의 신청  |
| 404  | 대상 없음 또는 삭제됨       |
| 409  | 정원·중복·수정 정책 충돌    |

## 작성 규칙

- TypeScript strict 사용. 소스와 테스트에 명시적 any 없음. HTTP 헤더는 IncomingHttpHeaders, 오류 응답은 unknown에서 좁혀 처리. 프론트의 성공 JSON 응답은 동일 서버의 계약을 제네릭 반환 타입으로 표현하며 별도의 런타임 스키마 검증은 하지 않음.
- 변수/함수 camelCase, 클래스/인터페이스 PascalCase, 상태값 대문자 문자열.
- 파일은 역할별 소문자 이름, 날짜 필드는 `At`, 운영 기간은 요구사항의 `startDate/endDate` 유지.
- 시각은 UTC ISO 문자열로 정규화한 후 비교합니다. UI는 KST 고정.
- 상태를 직접 외부로 노출하지 않고 읽기와 반환 시 복제합니다.
- 테스트는 구현 세부값보다 관찰 가능한 업무 규칙과 실패 시 불변성을 검증합니다.
- 권장 커밋: `feat:`, `fix:`, `test:`, `docs:`, `refactor:` 접두사 + 변경 목적.

## 확장 순서

1. 저장소 인터페이스 추출 후 Postgres 구현 추가. 신청·이력 저장을 하나의 트랜잭션으로 유지.
2. room 행 잠금 후 활성 인원 검사, 신청 유니크 제약. 적절한 인덱스와 서버 측 페이징.
3. 세션/JWT 기반 신원, 강사별 소유권 및 워크스페이스 경계.
4. 목록 페이징과 더 세분화된 공통 UI 컴포넌트 추출.
5. 알림은 저장 성공 이후 outbox 기반 처리. 실패한 알림이 예약 트랜잭션을 되돌리지 않도록 설계.
6. 로그, 백업, 장애 복구, 비밀 관리, 배포 파이프라인.

시간 입력은 분·초·밀리초 정밀도를 그대로 KST/UTC 사이에서 변환합니다. 이력에 0이 아닌 초·밀리초가 있으면 화면에서도 표시합니다.

## Vue 컴포넌트 경계

- App.vue: 메뉴 이동, 현재 페이지 조합, 저장 알림과 타이머 정리.
- EntryScreen.vue: 입장 전 역할/학생 선택, 서버 재확인, 성공 시 enter 이벤트.
- RoomList.vue: 검색/필터, 운영 요약, 목록과 신청 요청 이벤트.
- RoomDetail.vue: 운영 정보, 방문 예정 학생, 변경 이력과 수정/삭제 요청 이벤트.
- StudentList.vue: 학생 검색과 수정/삭제 요청 이벤트.
- MyVisits.vue: 본인 신청 상태와 변경/취소 요청 이벤트.
- WorkspaceDialog.vue: 폼 상태, 확인창, 저장 API 호출, 중복 제출 방지, 포커스 관리. defineExpose로 허용된 열기 동작과 busy/isOpen 상태만 부모에 제공.

목록/상세 컴포넌트는 props를 수정하지 않고 타입이 명시된 emit으로 작업을 요청합니다. 서버 상태는 기존 workspace가 소유하며 모든 저장 뒤 재조회합니다.
