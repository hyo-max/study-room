## 결론

**기능 기준: 필수 9개, 선택 3개가 구현되어 있고 검증을 통과했습니다.** 처음 구현에 경계 조건 문제가 있었으며 이번 점검에서 수정했습니다. 구현 완료와 제출 완료는 다릅니다. GitHub 저장소 업로드 및 링크 제출, 메일·문자 발송은 아직 수행하지 않았습니다.

점검 기준은 사용자가 제공한 원문입니다. 원문에 없는 좌석 지정, 알림, 출결, 로그인, 강사별 소유권 등을 필수 요구사항으로 추가하지 않았습니다.

## 발견하여 수정한 문제

### 1. 운영/방문 시간의 초·밀리초 손실

기존 `inputDate`가 분까지만 잘라냈습니다. `09:00:30.125` 시작 자습실의 기본 방문 시각이 `09:00`이 되어 유효한 기본 신청조차 운영 기간 위반으로 거절될 수 있었습니다. 이름·정원만 수정해도 운영 시간이 의도치 않게 바뀔 수 있었습니다.

- 수정 전 테스트에서 `00:00:30.125Z`가 `00:00:00.000Z`가 되는 실패를 실제 확인.
- 초가 포함된 입력에는 `:00`을 추가하던 코드도 잘못된 ISO 문자열을 만들었음.
- KST 변환을 별도 모듈로 분리하고 정밀도를 보존. 입력 step=0.001, 분/초/밀리초 입력 지원.
- 화면에도 연도와 0이 아닌 초·밀리초를 표시해 변경 내역의 모호함을 줄임.
- 단위 테스트 및 브라우저 기본 경계 신청 성공, 편집 폼의 원래 값 유지, 재시작 후 원본 저장값 확인.

### 2. 삭제된 학생 선택과 학생 0명 상태

기존에는 학생 ID 1을 기본값으로 두고 목록·학생·내 신청을 Promise.all로 한 번에 읽었습니다. 선택 학생이 삭제되면 내 신청 조회가 404가 되어 정상 목록 갱신까지 실패했습니다.

- 학생 목록을 먼저 확인하고 존재하지 않는 선택은 첫 유효 학생으로 전환.
- 학생 0명일 때 잘못된 내 신청 요청 생략, 등록 안내 표시, 신청 버튼 비활성화.
- 상태 테스트와 브라우저에서 선택 학생 삭제 후 김민준으로 자동 복구 확인.

### 3. 늦은 조회 응답이 현재 화면을 덮어쓰는 경합

기존 목록 요청은 일부 버전 검사가 있었지만 상세 조회/상세 갱신 이후에는 없었습니다. 메뉴·역할·학생을 바꾸거나 다른 상세를 연 뒤 오래된 응답이 화면을 다시 바꿀 수 있었습니다.

- workspace.ts로 상태/API 흐름 분리.
- 목록 요청 버전, 상세 요청 버전, 역할/학생 신원, 현재 상세를 함께 확인.
- 다른 창에서 삭제된 상세는 재조회 시 닫음.
- 지연 응답을 직접 제어하는 회귀 테스트 5개와 연결 실패/재시도 테스트 확인.

### 4. 이력 시간순 정렬이 삽입 순서에만 의존

기존에는 배열의 삽입 순서 그대로 반환했습니다. 서버 시계가 뒤로 조정되는 등 생성 시각과 삽입 순서가 달라지는 경우 시간순이라는 표시를 보장하지 못했습니다.

- createdAt 오름차순, 동일 시각은 id 오름차순으로 명시적 정렬.
- 생성 시각과 ID가 다른 순서인 데이터를 넣어 검증.

### 5. KST 새벽의 초기 자습실 날짜

초기 데이터의 ‘다음날’ 계산이 UTC 날짜 기반이라 KST 새벽에는 당일 자습실이 생성될 수 있었습니다.

- KST 달력 날짜를 기준으로 다음날 09:00 생성.
- KST 새벽과 저녁 시각 모두 검증.

### 6. 역할 오류 응답과 키보드 모달 배경

- 강사가 학생 전용 내 신청 API를 호출하면 404였던 응답을 역할 오류 403으로 일관되게 수정.
- 모달 표시 중 배경을 inert로 처리하여 포커스/키보드로 배경을 조작하는 경로 차단.

## 테스트·실행 증거

- 자동 테스트 최종 **49개 통과: API 36개 + 프론트 13개**.
- API 테스트에는 실제 HTTP 동시 요청, CRUD, 소유권, 상태 전이, 기간·정원 충돌, 삭제, 저장 실패 복구가 포함됨.
- 프론트 테스트에는 정밀도 보존, 학생 삭제·0명, 오래된 응답, 상세 삭제, 서버 연결 실패 복구가 포함됨.
- 기존 node_modules/dist/data가 없는 별도 복사본에서 `npm ci --offline` 성공. 이미 다운로드한 npm 캐시를 사용했으며 lockfile 기반 설치를 검증함.
- 리팩터링 후 최종 제출 ZIP을 새 폴더에 풀고 독립 설치한 상태에서 49개 테스트, 전체 빌드 및 포맷 검사 통과.
- 실제 `PORT=3101 npm start`로 빌드된 Vue 정적 파일과 Nest API 제공 확인.
- 브라우저에서 학생 생성/수정, 자습실 생성/정원 수정, 신청/시간 변경/취소/재신청/이력, 자습실 삭제/자동 취소, 학생 삭제/선택 복구 확인.
- 프로세스를 종료하고 `npm start`로 다시 실행하여 deletedAt, CANCELLED 상태, APPLIED→CHANGED→CANCELLED→REAPPLIED→CANCELLED 5개 이벤트, 초·밀리초 시각 보존 확인.
- 테스트용 독립 서버는 점검 후 종료. 기존 미리보기 데이터에는 검증용 학생·자습실을 만들지 않았음.

## 요구사항 위반은 아니지만 남아 있는 한계

1. **실제 로그인 없음.** 역할 헤더는 인증 수단이 아닌 데모 선택 방식. 원문에서 생략 허용. 공개 운영에 쓰기 전 실제 인증 필요.
2. **다중 프로세스 공유 저장 미지원.** 같은 파일을 여러 서버가 동시에 쓰면 안전하지 않음. 단일 프로세스 조건에서 동시 요청 검증. 원문은 다중 서버를 요구하지 않음.
3. **삭제된 자습실의 강사용 보관함 화면 없음.** 자동 취소 이력은 파일에 보존되지만 삭제된 상세의 별도 조회 UI/API는 없음. 원문은 삭제된 자습실 목록 제외를 요구하며 보관함은 요구하지 않음.
4. **명시한 정책을 면접에서 설명해야 함.** 정원/기간 충돌 거절, 취소 후 같은 ID 재사용, 과거 신청 허용은 원문에 없는 해석을 문서화한 것임.
5. **실제 원격 CI와 타 운영체제 검증 미실행.** Node.js 22/24 GitHub Actions 설정만 작성. 현장 실행 증거는 macOS Node.js 24.
6. **아이콘 패키지 deprecated 경고.** lucide-vue-next는 설치 경고가 있지만 설치·빌드는 성공. 현재 작업 범위의 기능 결함은 아니며 후속 유지보수 때 새 패키지로 이동 가능.
