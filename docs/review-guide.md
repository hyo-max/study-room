# 실행 시연과 코드 설명 가이드

## 5분 시연

1. `npm ci && npm run dev` 실행 후 localhost:5173 접속.
2. 진입 화면에서 강사를 선택한 뒤 최대 인원 1명의 자습실 생성.
3. 나가기 → 학생 → 김민준을 선택해 입장 → 해당 자습실 방문 신청.
4. 나가기 후 다른 학생으로 입장 → 정원 마감 확인.
5. 나가기 후 김민준으로 입장 → 내 방문 신청 → 시간 변경.
6. 나가기 후 강사로 입장 → 상세에서 신청/변경 이력 확인.
7. 해당 신청 시각보다 늦게 운영 시작을 변경 → 충돌 메시지 확인.
8. 학생으로 취소 → 자리 복원 → 재신청.
9. 강사로 자습실 삭제 → 학생 신청이 취소 및 삭제된 자습실로 표시되는지 확인.
10. 서버를 종료·재시작해 데이터 보존 확인.

## 설명할 수 있어야 할 질문

**왜 JSON인가요?**
설치 없이 로컬 실행 가능한 제출물을 우선했습니다. 과제가 JSON을 허용하며 데이터 규모가 작습니다. 운영 시스템이라면 관계·유일성·트랜잭션·복구가 필요한 DB로 전환합니다.

**동시에 신청하면 정원을 넘지 않나요?**
Store.transaction에는 await가 없고 단일 Node 프로세스에서 검증과 파일 저장을 한 동기 구간으로 실행합니다. HTTP 테스트가 한 자리로 6개 동시 요청을 보내 성공 1개/409 5개를 확인합니다. 여러 프로세스가 같은 파일을 공유하는 상황은 지원하지 않습니다.

**DB로 바꾸면 어떤 잠금을 사용하나요?**
자습실 행을 잠근 뒤 활성 신청 수를 검사하고 신청과 이력을 하나의 트랜잭션으로 저장합니다. 신청 유니크 제약도 추가합니다. 수정/삭제도 같은 자습실 잠금을 사용해야 합니다.

**왜 신청과 이력을 분리했나요?**
현재 신청 목록은 상태를 바로 읽고, 이력은 추가 전용으로 보존합니다. 매 조회마다 이벤트를 재생하지 않아도 되어 단순합니다.

**취소 후 재신청은 중복 아닌가요?**
같은 학생/자습실의 Visit 객체를 재활성화합니다. ID는 유지하고 REAPPLIED 이벤트를 남깁니다.

**변경 시 기존 신청을 자동으로 옮기지 않은 이유는요?**
학생이 선택한 시간의 의미를 보존하기 위해 정원/기간 충돌은 거절했습니다. 삭제만 명시적으로 일괄 취소합니다.

**지금의 권한 검사는 안전한가요?**
로그인 생략 데모입니다. 헤더로 역할을 선택하므로 실제 사용자 인증은 없습니다. 실서비스에서는 신뢰 가능한 인증 정보에서 Actor를 구성해야 합니다.

**가장 먼저 개선할 부분은요?**
DB 트랜잭션과 실제 인증, 이후 페이징·관측 가능성입니다.

## 코드 읽는 순서

1. `store.ts`의 타입 및 transaction.
2. `service.ts`의 apply → changeVisit → saveRoom → deleteRoom.
3. `main.ts`의 모듈 provider와 라우트.
4. `inputs.ts`의 unknown 검증과 정규화된 입력 타입.
5. `workspace.ts`의 api/load/detail과 `App.vue`의 페이지 조합.
6. `components/WorkspaceDialog.vue`의 submit과 목록 컴포넌트의 props/emit 경계.
7. `service.test.ts`, `http.test.ts`, `store.test.ts`와 프론트 `workspace.test.ts`, `date-time.test.ts`의 실패 조건과 불변성 검증.
